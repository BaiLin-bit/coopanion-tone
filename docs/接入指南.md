# 接入指南（可选）

「去 AI 味」扩展本身**不改任何人的代码**。它提供两样东西：

1. `deai_check` 工具和一段提示词——让模型自己检查，但实测它很少主动用
2. 一个只监听回环的**检查服务**——谁想让自己的发言被拦，就在发送前问一句

这份文档讲第 2 种：怎么把「发送前检查」接到各个 World 上。

> **这是可选的。** 不接也能用扩展，只是面板里不会有数据，也拦不住任何话。

## 服务接口

默认端口 `18770`（可用环境变量 `COOPANION_TONE_PORT` 改），只绑 `127.0.0.1`。

```
POST /check
  { "text": "<要发出去的正文>", "where": "<来源名>" }
→ { "ok": true, "level": "通过|轻|中|重", "density": 5.7,
    "hits": "破折号补丁腔、三项等长", "block": "拦截文案" 或 null }

POST /note
  { "text": "<确实发出去了的正文>", "where": "<来源名>" }
→ { "ok": true }        // 只记账，给面板用

GET /health
→ { "ok": true, "service": "coopanion-tone", "version": 1 }
```

`block` 非 null 就**别发**，把它原样当工具结果返回，模型会重写。

## 三条硬性要求

1. **原文原样传进去**：不要先截断、不要先清洗表情标签，否则判不准。
2. **`block` 非 null 就不要发**：否则等于白接。
3. **别把 `block` 的内容发给对方**：那是给模型自己看的。

## 各处怎么接

### QQ（`cortico-world-qq-final-beta`）

文件：`<数据目录>\extensions\node_modules\cortico-world-qq-final-beta\src\world.ts`
位置：`qq_send` 工具的 handler 里，`const text = String(args.text ?? '').trim();` 之后。

```ts
const r = await fetch('http://127.0.0.1:18770/check', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ text, where: 'qq_send' }),
}).then((x) => x.json());
if (r.block) return { text: r.block, failed: true };
```

发送成功后补一条记账：

```ts
void fetch('http://127.0.0.1:18770/note', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ text, where: 'qq_send' }),
}).catch(() => {});
```

### B站评论（`cortico-world-bili-scroller`）

文件：`...\cortico-world-bili-scroller\src\world.ts`
位置：`commentTool()` 里，`const detail = await this.bili.detail(...)` 之前，变量名是 `message`。

### QQ 空间（`cortico-world-qzone-alont1`）

文件：`...\cortico-world-qzone-alont1\src\world.ts`
位置：`qzone_post` 工具的 handler 里，变量名是 `content`。

### 桌宠气泡（`cortico-world-desktop-pet`）

文件：`<安装目录>\resources\app\node_modules\cortico-world-desktop-pet\src\world.ts`
位置：`say()` 方法里，`beats.map((b) => b.text).join('')` 就是正文。

> 气泡建议只记账、不拦：它有 TTS 和动画，硬拦会卡在「想说话说不出来」。

## 让 AI 帮你改

把下面这段原样粘给你的 AI（已经包含端口、接口、要求和失败处理）：

```
帮我改一下这个 Coopanion 安装里的发言出口，让它在发送前先问一下本地的腔调检查服务。

服务地址：http://127.0.0.1:18770/check
方法：POST，Content-Type: application/json
请求体：{"text": "<要发出去的正文>", "where": "<来源名，比如 qq_send>"}
返回：{"ok":true,"level":"通过|轻|中|重","density":数字,"hits":"命中的毛病","block":null 或 "拦截文案"}

要求：
1. 调用前先把原文原样传进去（不要先截断、不要先清洗）。
2. 如果返回的 block 不是 null，就不要发送，把 block 原样作为工具结果返回（并标记失败），让模型重写。
3. 如果 block 是 null，照常发送，不要改动原有逻辑。
4. 只改发送那一处，别动别的功能。
5. 改之前先备份文件；改完告诉我：改了哪个文件、哪一行、怎么回滚。
6. 如果找不到发送的那处，或者文件结构和描述对不上，就停下来问我，不要乱猜。
```

## 风险

**改的是 Coopanion 安装目录和扩展目录里的文件，升级或重装会被覆盖。**

- 改前备份：`Copy-Item world.ts world.ts.bak`
- 记下改了哪几行，升级后照着补
- 或者干脆别接：不接只是少一个功能，不会坏任何东西

## 为什么不做成「装上就自动拦」

Coopanion 没有「发送前钩子」这种扩展点。World 只能声明：工具、提示词、面板、配置、事件。

而事件流是**发送之后**才记录的（QQ 世界甚至根本不写出站事件），所以扩展自己看不到「即将发出的话」，更拦不住。

所以想拦，只能由发送方主动来问——这就是这个服务存在的理由。
