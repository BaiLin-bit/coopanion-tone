# 接入指南（可选）

「去 AI 味」扩展本身**不改任何人的代码**。它提供两样东西：

1. `deai_check` 工具 + 一段提示词——让模型自己检查（实测它很少主动用）
2. 一个只监听回环的**检查服务**——谁想让自己的发言被拦，就在发送前问一句

这份文档讲第 2 种。

> **这是可选的。** 不接也能用扩展，只是面板里没有数据，也拦不住任何话。

---

## 先确认你装的是哪一个

Coopanion 里同一个功能可能有好几个包，变量名和工具名都不一样。接之前先对一遍：

```powershell
# 1. 看启用了哪些 World（键名就是 world id）
Get-Content "$env:USERPROFILE\Coopanion\data\home\companion\config.json" -Raw |
  ConvertFrom-Json | Select-Object -ExpandProperty worlds | Get-Member -MemberType NoteProperty | Select-Object -ExpandProperty Name

# 2. 看装了哪些包
Get-Content "$env:USERPROFILE\Coopanion\data\extensions\package.json" -Raw |
  ConvertFrom-Json | Select-Object -ExpandProperty dependencies
```

本指南覆盖的四个，标识如下：

| 世界 | 包名 | world id | 工具名 | 文件 |
|---|---|---|---|---|
| QQ | `cortico-world-qq-final-beta` | `qqbot` | `qq_send` | `…\extensions\node_modules\cortico-world-qq-final-beta\src\world.ts` |
| B站 | `cortico-world-bili-scroller` | `bili-scroll` | `biliscroll_comment` | `…\cortico-world-bili-scroller\src\world.ts` |
| QQ空间 | `cortico-world-qzone-alont1` | `qzone` | `qzone_post` | `…\cortico-world-qzone-alont1\src\world.ts` |
| 桌宠 | `cortico-world-desktop-pet` | `desktop-pet` | `pet_say` | `<安装目录>\resources\app\node_modules\cortico-world-desktop-pet\src\world.ts` |

> ⚠ **别搞混 QQ 的两个包**：`cortico-world-qq`（world id 是 `qq`，工具名 `qq.send`，带点）和 `cortico-world-qq-final-beta`（world id 是 `qqbot`，工具名 `qq_send`，带下划线）。两者的文件位置、方法名、返回结构都不同，照错一个就白改。

> ⚠ `data\extensions\node_modules\` 下的目录常常是指向 `.pnpm\...` 的链接。**改的时候改真实路径**（在文件上右键看属性，或 `Get-Item <路径> | Select-Object Target`）；改链接目标才生效。

## 服务接口

默认端口 `18770`（环境变量 `COOPANION_TONE_PORT` 可改），只绑 `127.0.0.1`。

```
POST /check
  { "text": "<要发出去的正文>", "where": "<来源名，随便起>" }
→ { "ok": true, "level": "通过|轻|中|重", "density": 5.7,
    "hits": "破折号补丁腔、三项等长", "block": "拦截文案" 或 null }

POST /note
  { "text": "<确实发出去了的正文>", "where": "<来源名>" }
→ { "ok": true }        // 只记账，给面板用

GET /health
→ { "ok": true, "service": "coopanion-tone", "version": 1 }
```

**判定规则：`block` 非 null 就别发。** 把 `block` 原样当工具结果返回，模型会重写。

---

## 三条硬性要求

1. **原文原样传**：不要先截断、不要先清洗表情标签，否则判不准。
2. **`block` 非 null 就不要发**：否则等于白接。
3. **别把 `block` 的内容发给对方**：那是给模型自己看的。

## QQ：`cortico-world-qq-final-beta`

```
包名     cortico-world-qq-final-beta（本机 0.1.64-beta.6）
world id qqbot
工具名   qq_send
文件     <数据目录>\extensions\node_modules\cortico-world-qq-final-beta\src\world.ts
位置     qq_send 的 handler 里，`const text = String(args.text ?? '').trim();` 之后
变量     text
返回     `{ text, failed: true }`（也可以返回字符串，但那就无法标记失败）
```

**示例**（照着改，变量名和返回结构以上表为准）：

```ts
// text 已在上文定义
const r = await fetch('http://127.0.0.1:18770/check', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ text, where: 'qq_send' }),
}).then((x) => x.json());
if (r.block) return { text: r.block, failed: true };
```

发送成功后补一条记账（不然面板只有「拦下」，看不到「发出」）：

```ts
void fetch('http://127.0.0.1:18770/note', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ text, where: 'qq_send' }),
}).catch(() => {});
```

## B站：`cortico-world-bili-scroller`

```

world id bili-scroll
工具名   biliscroll_comment
```

**示例**：

```ts

```

> 这个文件在你自己的项目目录时（`file:` 安装），改源码后要重新安装或改 `.pnpm` 里的副本才生效。

## QQ 空间（QQ 扩展自带）：`cortico-world-qq-final-beta`

如果你用的是 QQ 扩展自带的空间发帖，它在**另一个文件**：

```
文件     …\cortico-world-qq-final-beta\src\qzone.ts
位置     post() 方法里，`if (!content) return ...` 之后
变量     content
返回     `{ ok: false, error: '...' }`
```

回复评论在 `replyComment()`，变量 `text`，返回 `{ ok: false, error }`。

**注意返回结构和 QQ world.ts 不一样**：这里不是 `failed: true`，是 `ok: false`。

## 让 AI 帮你改（推荐）

上面每一段都是**某个包的某一处**的写法，变量名、返回结构、是否 async 都会变。真正省事的办法是把下面这段给 AI，让它读实际代码：

```
帮我改一下这个 Coopanion 安装里的一个发言出口，让它在发送前先问一下本地的腔调检查服务。

服务地址：http://127.0.0.1:18770/check
方法：POST，Content-Type: application/json
请求体：{"text": "<要发出去的正文>", "where": "<来源名，比如 qq_send>"}
返回：{"ok":true,"level":"通过|轻|中|重","density":数字,"hits":"命中的毛病","block":null 或 "拦截文案"}
另一条接口（可选，只记账）：POST http://127.0.0.1:18770/note，同样的 body，返回 {"ok":true}

目标：<在这里写清楚改哪个，比如 "cortico-world-qq-final-beta 的 qq_send 工具，world id 是 qqbot">

要求：
1. 调用前先把原文原样传进去（不要先截断、不要先清洗）。
2. 返回的 block 不是 null 就不要发送，把 block 原样作为工具结果返回并标记失败，让模型重写。
3. block 是 null 就照常发送，不要改动原有逻辑。
4. 只改发送那一处，别动别的功能。
5. 改之前先备份文件；改完告诉我：改了哪个文件、哪一行、怎么回滚。
6. 如果文件结构和描述对不上（比如找不到那个工具、变量名不一样），停下来问我，不要猜。
7. 注意 data\extensions\node_modules 下可能是指向 .pnpm 的链接，要改真实路径。
```

---

## 风险

**改的是 Coopanion 安装目录和扩展目录里的文件，升级或重装会被覆盖。**

- 改前备份：`Copy-Item world.ts world.ts.bak`
- 记下改了哪几行，升级后照着补
- 或者干脆别接：不接只是少一个功能，不会坏任何东西

## 为什么不做成「装上就自动拦」

Coopanion 没有「发送前钩子」这种扩展点。World 只能声明：工具、提示词、面板、配置、事件。

而事件流是**发送之后**才记录的（QQ 世界甚至根本不写出站事件），所以扩展自己看不到「即将发出的话」，更拦不住。

所以想拦，只能由发送方主动来问——这就是这个服务存在的理由。
